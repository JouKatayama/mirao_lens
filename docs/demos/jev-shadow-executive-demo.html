技術デモ 03 / 03 ・ 合成ケース
Phase 3 measured → Phase 4 decision

実装済みの位置と、次に変わる境界。

代表の理解「3でJevが数値化判定し、4でOpenAIが文章化」は、目指す段階分離としては近い。ただし現行の本番経路はその順序で動いていない。

現在の本番

OpenAI 生成1回の構造化出力が、Flash Brief の文章・キーワード・potential_score・identity_status・claim_type を同時に作る。Jev の値は使わない。

Jev 0回

生成と判定はこの呼び出しで同梱。

PHASE 3（今回、実測可能に）

既存の合成ブリーフを Jev 5リクエストで shadow 評価。8次元採点、SAY THIS、POTENTIAL、Identity、Mutual Value claim を測定し JSON に記録。

75回 / 全測定

3ケース × 5反復 × 5評価。品質の合否や閾値は置かない。

PHASE 4 で具体的に変えるなら

生成器が候補文を作る → Jev が型付き質問で候補・点数・分布を判定する → アプリが結果の扱いを決める → 必要な場合だけ生成器が確定結果を文章へ反映する。最後の OpenAI 再文章化は未実装の設計選択であり、呼び出し回数・遅延・コストは未測定。
